这次拆的是智慧树，就是那个「大学生都在上面刷网课」的平台，官方名字叫知到。

学校平台里不是每家都好啃：图书馆检索接口免登录公开，学习通全是明文 HTTP 加 JSON，协议拿过来就能用。智慧树没这个运气。它的请求带加密和浏览器环境校验，社区里纯协议向的项目死了一批，zhihuishu-tool 2023 年归档，zhihuishu-cli 失修，还在活跃的全是挂浏览器的刷视频脚本。我调研时给这条线下的结论写在侦察文档里，四个字：作业空白。视频挂机有现成轮子，作业读取没有任何人做过。

所以这篇的故事不是把一套明文协议抄进 Rust，而是先承认抄不了，再想办法绕。绕的产物是一台挂在无头浏览器上的采集容器，和一段 nag 了我十二天的「假作业」。

先交代边界：所有操作只针对我自己的账号，只读，不向平台写回任何数据，考试式作业只提醒人工完成，这条红线全文适用。

## 让页面自己跑，我在旁边听

请求加密加浏览器校验，意味着我拼不出一个合法请求。但页面的 JS 能。它自己的代码负责签名、负责加密、负责带上所有校验参数，页面能正常打开，请求就是合法的。

那就不拼请求了。让真浏览器把页面跑起来，我在旁边听它发出的每一个响应。采集器用 Playwright，跑在独立容器里，镜像直接用官方的 Playwright Python 版，自带 Chromium 和全部系统依赖，再加一个 Xvfb 提供虚拟显示。它和主程序之间零网络耦合，通信靠一个文件：采集器把抓到的东西写进 `report.json`，主程序读这个文件。sidecar 挂了，主程序照常跑，只是数据不新鲜。

监听响应的核心是个可拆卸的回调：

```python
class CollectHandle:
    """可移除的响应采集器."""

    def __init__(self, page, matcher):
        self.page = page
        self.matcher = matcher
        self.captured: list = []

    async def start(self):
        async def on_response(resp):
            try:
                if "json" not in (resp.headers.get("content-type") or ""):
                    return
                body, req = await self.matcher(resp)
                if body is None:
                    return
                self.captured.append({"body": body, "req": (req or "")[:300]})
            except Exception:
                pass

        self._cb = on_response
        self.page.on("response", on_response)

    def stop(self):
        if self._cb:
            self.page.remove_listener("response", self._cb)
```

matcher 按域名筛：作业详情的载荷在 `student-homework` 域，小组作业走 `groupHomeworkDetail`，普通作业走 `detail`。页面打开后等八秒。不是页面加载完就能抓到，前端要自己发后续请求，八秒是实测出来的等待值。

抓到的原始报文会归档成 `detail_api.json`。这是个习惯：逆向期的原始响应永远留一份，字段映射写错了可以拿原文重新校准。老版课程（wenda 平台）的字段名和新版完全不同，就是拿留档的原始条目逐个对出来的。

## 抓的是待办流，不是作业列表

动手之前有个问题要想清楚：作业列表从哪来。

答案让人意外：智慧树没有「作业列表」这个页面。课程页里，作业、考试、课堂活动、讨论混在同一条时间流里展示；平台另有一个全局「待办」聚合页，接口叫 `findNoFinishTaskTotal`，语义是「你还有什么没做」。

我们的采集就抓这两个地方。这个设计埋了一个雷，后面第五节炸。这里先把结论放了：抓的是待办流，而待办流里不全是作业。

每条任务抓回来以后，整理成一份契约。报告文件长这样（注释是说明，实际文件没有）：

```jsonc
{
  "generated_at": "2026-10-19 15:30:00",
  "login_ok": true,                 // false 时每日提醒一次「需重新登录」
  "courses": [{
    "title": "职业生涯规划",
    "tasks": [{
      "activity_task_id": "9VDE…",  // 平台任务 ID，幂等键的一半
      "title": "第五节课 课前测",
      "kind": "assignment",         // assignment | group | exam | other
      "start_at": "2026-10-23 00:00:00",
      "end_at": "2026-10-31 00:00:00",
      "completed": false,
      "total_score": 20.0,
      "exam_duration_minutes": null, // >0 即考试式
      "late_submit": false,          // 详情页 isDelay
      "content": "作业描述…",
      "attachments": [
        {"name": "作业要求.docx", "file": "attachments/{task_id}/作业要求.docx"}
      ]
    }]
  }]
}
```

主程序解析这份契约时开了 `deny_unknown_fields`：平台侧字段一变，解析直接报错，而不是静默丢字段。契约演进靠报错驱动，比靠人眼盯着 diff 靠谱。

## 一份 nag 了我十二天的作业

10 月 22 日，一条「随堂作业」进了提醒系统。它是某门思政课的课堂分层练习，正文是「基础：」「进阶：」「拓展：」三档弹性任务。平台给它挂了一个结束时间——10 月 19 日零点，其实就是那节课下课的时间点，不是什么提交截止。

但当时系统不认识这些。它只看到：一条有标题、有截止时间、未完成的任务，截止时间已过。于是它按规则提醒我：这条作业过期了。第一天我以为是老师忘了关，第二天觉得奇怪，第三天开始烦。到我翻后台的时候，它已经连着 nag 了十二天，提醒记录攒了十二条。

这十二天的根源不在提醒逻辑，在采集端：待办流里的课堂活动，被当成真作业抓了回来。平台自己是有类型字段的，`kind` 有四种取值：`assignment` 真作业、`exam` 考试、`group` 小组活动、`other` 其他。那条随堂练习是 `other`。之前系统不看这个字段，全按真作业处理：建待办、进 Obsidian、过期了每天提醒。

## 能抓到的，不一定是作业

我把排查结论讲给朋友听的时候，他反问了一句：

> ？怎么可能，能爬获取到的不就是作业吗？

这句反问问到了点子上。直觉上，「作业」就是平台上那些需要交的东西，爬到了自然就是。但拆开看，我们爬的位置根本不是作业列表，是平台的待办流。待办流的设计语义是「凡未完成且带截止时间的条目都往里塞」。老师在课堂上发一个随堂互动，平台也给它挂截止时间，它就进了待办流。老师可能压根没打算收。

「能爬到」只说明「平台把它放进了这个接口」，不说明「它是我该交的作业」。接口的边界和业务的边界不是一回事，这件事在任何平台都成立，只是平时碰不到反例。

修法是三层，一层比一层重：

第一层，类型过滤。`kind` 不是 `assignment` 也不 `group` 的，先降级处理。

第二层，文本信号。平台没有「选做」字段，只能从标题和正文猜。猜的规则我定得很保守，宁缺毋滥，只认高置信的词：

```rust
fn is_optional(task: &ZhihuishuTask) -> bool {
    const HINTS: &[&str] = &[
        "选做", "选答", "自愿", "附加题", "加分题",
        "额外加分", "课堂表现加分", "不作要求", "不做要求", "学有余力",
    ];
    let text_hit = |s: &str| HINTS.iter().any(|h| s.contains(h));
    if text_hit(&task.title) {
        return true;
    }
    match task.content.as_deref() {
        Some(content) => {
            text_hit(content)
                || (content.contains("基础：")
                    && (content.contains("进阶：") || content.contains("拓展：")))
        }
        None => false,
    }
}
```

「基础：」加「进阶：」这对信号专门治分层练习——平台的课堂弹性任务几乎都用这个话术。选做任务照常展示，但标注「（选做）」，并且不因为临期升级优先级。代码注释里那句话我写着写着觉得像自己的人生建议：不强制交的东西，不值得紧急推送。

第三层，忽略名单。前两层都拦不住、我又确认了不用的，进配置里的忽略名单，规则是「课程关键词｜任务关键词」，完全跳过：不落库、不建待办、不进 Obsidian、不提醒。

那条 nag 了十二天的随堂作业走完了整个流程：类型和信号词都命中，我确认，进名单。然后做了一次生产清理：删掉它的任务记录和十二条提醒记录，把误建的待办标成取消，删掉 Obsidian 里误建的文件夹。警告要消得干净，不然它换个字段又活过来。

顺带还修了一个连带 bug：有的作业说明只有一句话，比如「小组线下展示，提交视频」。按正文长度判断它不是实质作业，不建任务目录，但它偏偏是要真交东西的。后来给实质作业的判断加了三条通道：正文满五十字、带平台附件、或者干脆是小组作业，第三条无条件放行。一句话的小组作业说明不碍事，交付物是真的。

## 老师会改截止时间

提醒系统上线一个月后，我发现一个盲区：老师会改截止时间。

这听起来像废话，但对一个「首次见到就存快照，之后只看完成状态」的系统来说，它是致命的。初版的同步逻辑只同步 `completed` 字段，其余字段一概不更新。老师把 ddl 从周五改到下周三，我的快照里还是周五，待办里还是周五，提醒照着错误的日期响，我还以为系统很准。

刷新语义后来重写成三种，每轮轮询都会过一遍：

```rust
let reopened = old_completed && !completed;
let drifted = old_end.as_deref() != new_end.as_deref();

if reopened {
    // 已完成 → 未完成：老师打回或开放补交
    // 重建待办 + 提醒「作业重新开放」
} else if drifted {
    // 截止时间漂移：更新快照 + 待办 postpone
    // 提醒「截止变更：旧时间 → 新时间」
}

if completed {
    // 平台侧已完成 → 回勾待办，一次性
}
```

三种里最有用的是重开。已完成变回未完成，多数情况是老师打回重做，少数是开放补交。不处理的话，我这边显示「已完成」，待办也勾掉了，实际上活还在——这种状态错位比没有提醒更害人。

## 一个不报错的 bug，比 panic 难抓十倍

重写刷新逻辑的时候，回勾待办那里埋过一个 bug，值得单独记。

回勾成功后要把 `todo_synced` 标记写回快照，防止下一轮重复回勾。写回的调用是这样的：

```rust
// 文档必然已存在，必须带 revision 走 CAS——
// put_document(None) 是仅新建，写回会被静默丢弃，
// 导致作业总表永远显示未完成、每轮重复 complete。
self.store.put_document("zhihuishu_task", &key, Some(revision), &snapshot)?;
```

注释里写的就是我踩的坑：`put_document` 的第三个参数传 `None` 时语义是「仅新建」，文档已存在时这次写入被静默丢弃，不报错，不返回失败，什么都不发生。表现是每轮轮询都重新回勾一遍待办，作业总表永远显示未完成，而日志干干净净。

这类 bug 的讨厌之处在于它的三个特征全反着来：不崩溃（没有 panic 可查）、不报错（没有错误可搜）、还自带周期性（每轮都发生，看起来像「设计如此」）。存储层后来把「仅新建语义下写已存在的键」改成了显式报错，与其让下游静默吞掉，不如让错误在写入那一刻炸出来。

## 时间戳不该写进笔记

作业会同步进 Obsidian：一门课一个索引文件，未交的作业各建一个文件夹写作业说明。同步的原则是「内容无变化就不提交 git、不播报」，这个原则被一个时间戳打穿了。

早期版本往作业说明的 frontmatter 里写了 `updated` 字段，取值是当次轮询的时间。于是每一轮轮询，文件内容必然变化，「无变化不提交」永远不成立，git 里全是内容只差一个时间戳的提交，通知也跟着遭殃。

修法很朴素：笔记里只写业务事实——课程、任务、截止、状态、分数，不写任何「每轮都会变」的东西。想看「系统什么时候跑过」，日志里有，轮询报告里有，不需要污染笔记。这条经验后来写成了同步层的通用规则：凡是会进 git 的文件，内容必须是「事实的函数」，不能是「时间的函数」。

提醒本身也全走幂等键去重，规则一张表就说完了：新任务提醒一次，键是课程加任务 ID；临期和过期每日最多一次，键上追加日期；登录态失效每日一次；课程视频内容首次发布播报一次。过期作业只提醒一次这条，就是那条 nag 十二天的作业用血泪换来的特例倒逼出来的。

## 附件第一战：趁链接活着

作业说明常常带附件，老师的 docx、pptx 挂在详情页上。这是整个智慧树线里最麻烦的一块，分三战。

第一战是拿到文件。附件的下载地址藏在详情 API 的返回里，但位置不固定，有的在 `ossUrl`，有的在 `fileUrl`，还有的叫 `downUrl`，外层结构也随任务类型变。与其枚举位置，不如整个返回体递归一遍：

```python
def find_attachments(node, found: list) -> None:
    """递归在详情 API JSON 里找附件项(名称 + URL 的对象)."""
    if isinstance(node, dict):
        keys = set(node.keys())
        name = next(
            (node[k] for k in ("fileName", "name", "title")
             if k in keys and isinstance(node[k], str)),
            None,
        )
        url = next(
            (node[k] for k in ("ossUrl", "fileUrl", "url", "fileDownloadUrl", "downUrl")
             if k in keys and isinstance(node[k], str) and node[k].startswith("http")),
            None,
        )
        if name and url:
            found.append({"name": name, "url": url})
        for value in node.values():
            find_attachments(value, found)
    elif isinstance(node, list):
        for item in node:
            find_attachments(item, found)
```

递归的代价是可能捞进杂质，好在判断条件极简：有名字、有 http 开头的地址才算附件，实测没有误报。

下载有个时限问题。这些 URL 是带签名的，签名会过期，今天存下来的链接明天就可能打不开。所以策略定成：见到附件立刻下载文件本体，URL 不落库，落库的是下载好的文件。这一层和图书馆篇的 Referer 防盗链是同一个道理的两面：平台不想让资源裸奔，那你就别存裸奔的凭证，存结果。

下载走的是页面自带的登录态（`page.request.get`），直接打 OSS。抓取是幂等的：`attachments/{任务ID}/` 目录已存在就直接复用，不再访问平台，删目录强制刷新。单任务失败只降级，不影响整轮。

还有一层防御写在主程序的拷贝逻辑里：报告文件里的附件路径，只要有 `..` 段直接拒掉。契约文件是外部输入，路径可以构造，读文件之前先当它有恶意。

## 附件第二战：按格式分流

第二战是转换。docx 原件躺在 Obsidian 文件夹里，但 Obsidian 预览不了它，agent 读它也费劲，得转一份可读副本。

一开始我想当然：全都转 markdown。第一个反对意见来自 pptx。pptx 是版式文档，一根文本框一根文本框定位排版，转 md 等于把排版全扔了，转出来的东西既不好读也丢信息。被现实教育之后，规则改成按格式分流：

```rust
let written = match ext.as_str() {
    "docx" => self.pandoc_to_md(source, stem, &temp, vault, dest_base),
    "pptx" => soffice_to_pdf(source, name, stem, &temp, vault, dest_base),
    "xlsx" => xlsx_to_md(source, stem, &temp, vault, dest_base),
    _ => 0,
};
```

docx 是文字为主，pandoc 转 markdown，公式和嵌图都保得住；pptx 是版式为主，LibreOffice 渲染成 PDF，Obsidian 原生预览，保真度最高；xlsx 用 openpyxl 抽成 markdown 表格。三份工具都是现成的，没有自己造的必要。

pandoc 那步有个不起眼的坑：`--extract-media` 抽出来的图片路径，传绝对路径它会把绝对路径原样写进 markdown。所以转换在临时目录里跑，让 pandoc 产出相对路径，图片再统一搬进 `{stem}.media/`。stem 是附件文件名，同一作业文件夹里有多个附件时，图片各归各的目录，不会撞名。

原则一句话：转换产物只是可读副本，原件永远已经拷在旁边，格式以原件为准。哪天 pandoc 转丢了什么，原件还在。

## 附件第三战：裂图

第三战不是新功能，是用户（也就是我自己）在手机上看到的一条反馈：转出来的作业说明文档，图片全是裂的。

裂图的原因是引用路径。pandoc 抽出的图片写在 `media/xxx.png`，文件实际落在 `{stem}.media/xxx.png`，两边对不上；再加上部分旧笔记里的引用还带着 `attachments/` 前缀，而文件已经被拷进了作业文件夹，前缀成了死路。修法分三步：兜底扫描时补齐目录前缀，跳过 sidecar 自己放进附件目录的 `detail_api.json` 之类的元数据（它们不是作业附件），嵌图引用统一改写成 Obsidian 的 wikilink 格式——`![](media/x.png)` 在 Obsidian 里能不能解析取决于库配置，wikilink 则总是认。

这战没有技术含量，全是「两个模块各自都对，拼起来就是错的」的对账活。但裂图这种问题只有真实使用才会暴露：转换函数单测是绿的，图片文件也在盘上，坏的只是那行引用。

## 待办只往一个方向同步

作业和待办打通之后，一个自然的疑问是：我在待办里手动勾掉，平台那边会不会也交上？不会，也不该会。同步是单向的，平台到待办：平台显示完成，待办自动回勾；我在待办里手动勾掉，平台状态不动，作业没交就照样触发临期提醒。这个方向是唯一安全的——待办是「我打算做什么」的视图，平台是「事实是什么」的记录，事实不能被视图反向改写。

优先级也有一套小规则。考试式作业（限时或者带监考标志）直接标 🔒 加高优先级，remind_at 设在截止时刻；普通未交作业临期升级；选做任务永远不升级。考试式还有一条更硬的红线：采集器整体跳过，绝不进答题页，连它的详情页都不看，只读文本和网络响应，不点任何提交入口。作答草稿这种未来的功能，产出也必须经人工审核。这条在调研文档里写得很早，一直没变过：自动答题就是代写，代写和代签不一样，代签签的是「我到了」，代写交的是「我会了」。

## 收尾

现在的状态：智慧树的作业每晚由采集容器跑一轮，新作业提醒一次、临期每日一次、老师改 ddl 会被逮住、打回重做会被逮住、交完自动销账。作业说明和附件落在 Obsidian 的课程文件夹里，docx 有可读副本，pptx 有 PDF，和学习通的作业在学期总表里汇成一张清单，一条命令出全貌。

同一个生态里的几家平台，性格并不一样：图书馆大方，检索接口免登录随便调；学习通松散，明文协议但风控反应快；智慧树最设防，请求加密，页面校验，逼着你把真浏览器请出来替你办事。设防的平台未必更安全——它只是把「不信任客户端」做到了接口层，而只要人还是要用浏览器做正事，浏览器就永远是合法的客户端，也永远是逆向的入口。

作业这条线我反复强调的只有一件事：能抓到的，不一定是作业。接口返回什么和业务上该处理什么，中间隔着一层判断，这层判断没人替你做，平台不会帮你分，文档不会告诉你，只有那条 nag 了十二天的提醒会教你。
