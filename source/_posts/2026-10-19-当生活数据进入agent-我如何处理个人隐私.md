这次做水电监控和 QQ 机器人，我最担心的反而不是接口调不通，而是把生活信息顺手带出去。

学校、宿舍、姓名、手机号、校园卡登录状态、每天几点查水电，单看好像都没什么，拼在一起却可能定位到一个具体的人，甚至描出他的生活轨迹。

一个月下来，这套隐私处理经历了「搭起来」和「拆回去」两个阶段。有些防线留住了，有些当天上线当天就删了。这篇文章把整个过程摊开讲：最后留下来的东西很少，但每一条都知道自己为什么存在。

## 先分清：技术可以公开，生活定位信息要藏起来

会碰到的内容大致有两种。

一种是可以公开的技术信息：校园卡平台由哪些厂商提供、接口怎么签名、抓包思路是什么、Rust 模块怎么组织。这些对别人有参考价值，全部删掉反而没法复盘。

另一种是需要谨慎处理的生活信息：

- 学校名称、学校域名；
- 学工号、姓名、手机号、身份证和银行卡信息；
- 校区、楼栋、房间号；
- 校园卡登录 token 和私人配置；
- 水电余额、充值时间、每天查询的时间；
- QQ openid，以及私人聊天里的其他内容。

原则是把方法留下，把能定位到具体学校和个人的细节拿掉。写复盘时最容易犯的错误，是手机号知道打码，学校名和宿舍号却顺手写进去。所以发布前的检查范围是：学校统一写成「G 校」，域名只留结构不写真实地址，房间号用虚构占位，截图和日志重看一遍，不是只查正文。

生活隐私不是只有「证件号」那几样。学校 + 楼栋 + 房间 + 水电记录，本身就是一组很具体的位置和作息信息。

## 第一层：让 Agent 看到假值，而不是真值

这是整套体系的核心，也是最早做的一层。Worker 在把内容交给模型之前，先过一轮正则替换。

一开始规则很朴素：手机号、身份证、邮箱、银行卡、带前缀的中文姓名。用下来发现真正的漏网大户是另外两类。

一类是赋值形态的密钥。笔记里随手一记就是 `password: xxx`、`token = xxx`、`api_key: "xxx"`，甚至中文键「校园卡的密码：」。这类东西不带任何明显特征，纯靠格式识别。现在的规则覆盖了常见的键名写法（password/passwd/token/secret/api_key/access_token/client_secret），中文键的前缀边界也单独处理过：中文后面直接跟冒号时 `\b` 是不成立的，这种细节只有真跑过才知道。

另一类是结构特征明显的令牌。Bearer 头和 JWT 前缀 `eyJ` 开头，不依赖键名就能认出来。

命中之后不是全改成 `*`，而是换成一个随机的同类假值：手机号保持号码格式，身份证重新算合法校验位，银行卡满足 Luhn 校验，密钥换成一串长得像 key 的占位符。模型有时还需要理解数据结构，全部打星号会让它彻底看不懂任务。保留类型特征，比单纯抹掉更实用。

同一个任务里，同一个真值永远对应同一个假值，不然模型会以为这是好几个不同的东西。假值生成时还要做碰撞检查，不能撞上原文里已有的片段。任务结束后 Worker 把结果里的假值恢复回真值再回复 QQ，映射表只在本地，从进模型到回填，原文不出机器。

所以这一层做的事只有一件：减少特定个人信息直接进入模型请求，而不是让整个系统都不保存原文。

## 第二层：能隔离的就不脱敏

用了一段时间后意识到，替换是在打补丁，前提是内容先到了模型面前。更好的做法是让某些东西根本走不到那一步。

配置隔离。worker 容器加载的配置是裁剪版，整个 `sources` 段（各平台的登录凭据都住在这里）在导出时就被剔掉了。Agent 在容器里跑命令，拿到的是一份「干活的配置」，不是「全家的钥匙串」。

文件快照。让 Agent 整理 vault 文件时，它看到的不是文件系统，而是内联进提示的脱敏正文快照，单文件两万字符封顶、总量六万截断。Agent 的输出也被约束成结构化指令：移动哪里、删哪里、记什么待办，落盘由宿主代码执行。它从头到尾没有「读全文、写文件」的能力，自然谈不上把文件内容带出去。

周扫兜底。每周一凌晨全 vault 扫一遍明文密钥，形态库除了上面那些规则，还加了云厂商 AccessKey、Slack token、GitHub token、私钥头、带凭证的连接串。报告只有位置、规则名和脱敏预览，扫出来什么，我自己去处理。这是防我自己手滑。往笔记里贴个密码这种事，防线拦不住作者本人，只能事后喊一嗓子。

这三件事的思路是一致的：缩小 Agent 的可见面，比扩大替换规则更省力。正则写得再全也有漏的，但一个根本不存在的文件不可能泄露。

## 第三层：沙箱收窄

模型调用的内容脱敏了，剩下的口子是它的动作。Codex 有沙箱配置，我留了一个开关：默认还是历史行为，需要时可以切成 workspace-write，只能写工作区，网络访问默认关闭，某个任务真要联网得显式授权。

这层现在大部分时间是关着的。留它的原因不是天天用得上，而是失控时的下限：agent 被提示注入或者抽风乱写文件这种事，概率低但后果不可逆，开关放在那里，睡觉踏实一点。

## 我建了又拆掉的两道防线

这部分讲「不做什么」，可能也是全文最有意思的部分。

第一道是出站审计。思路很顺：所有发出去的通知和 vault 提交，先过一遍红区正则，命中就拦。听起来像入口脱敏的镜像，进关口，出口也查。做完跑了几周，一次真实命中都没有。想明白原因就拆了：入口脱敏做得够严，敏感信息根本到不了模型面前，出口扫的是「P0/P1 漏网的」，而这个漏网从来没发生过。代价倒是真实的：每条通知、每次提交都过正则，一旦误拦，整理、待办这些自动闭环直接卡死。为不存在的威胁持续付费，还引入新的故障点，不划算。

第二道是网络层域名审计。这道更曲折。思路是把全部容器的出站流量赶到自建代理上，记录「谁连了哪个域名」，白名单外的陌生域名推送告警。听起来很企业级，我甚至把 mihomo 日志级别调了、写了采集器、做了聚合插件，第一天就抓出四十个「陌生域名」，还挺有成就感。

然后我问了自己一个问题：这套东西防的是什么？

答案是：什么都防不了。我真正怕的是信息穿越，也就是密码、笔记内容被 agent 带出去。而 TLS 时代内容是加密的，域名审计只能看到「连了哪个域名」，看不到传了什么。泄露者用白名单里的正常域名（GitHub、CSDN 都在名单里）就能把内容带出去，审计一声不吭。它能抓到的只有「另开陌生通道」这种粗糙姿势，抓不住正经通道里的夹带。

所以这两道防线上线当天就删干净了。删之前留了 git 历史，以后想捡回来随时能捡。

这一轮下来我给自己立了个规矩：**每道防线必须能说出它对应哪个具体威胁，说不出来就是装饰品**。「企业都这么做」不是理由，企业做出口审计是因为它们的威胁模型里有横向移动和影子 IT，我一个小型个人系统没有。

## 权限控制也属于隐私保护

水电读数看起来只是两个数，但带上宿舍位置、充值时间和每日采集时间，就不再是数字了。

所以 QQ 查水电有两条限制：必须先绑定身份，不是随便谁发「水电」都能查；只允许单聊查看，群聊里提示去单聊，而不是把信息贴进群里。

什么内容能出现在什么会话里，和正则替换一样重要。

## 密码的正确位置

这一个月还有一个反复验证的判断：自动化几乎从不需要把密码交给模型。

以查作业为例：密码做的事是登录平台、拉数据，固定流程，交给代码；模型做的事是理解列表、判断哪个是新作业、要不要提醒，理解决策，不需要密码。这两件事根本不必发生在同一个地方。

所以 Ru41 的模式是：密码住在配置里，插件代码拿它去登录，模型只调用工具、只看到工具返回的结果。密码永远只存在于「代码到平台」这条线上。逆向新平台的时候确实有一瞬间需要凭据进对话，但那是开发期的一次性动作，沉淀成插件之后就回归这个模式了。

## 我也有没做完的地方

写到这里不能把话说满。

第一，QQ 收到消息时原文会先进任务数据库，替换发生在 Worker 调模型之前。「模型少看一点」和「本地不保存原文」不是一回事。

第二，学校名、校区、楼栋、房间号这些生活信息，没有通用的自动识别规则，还是靠本地隔离和发布前人工检查。正则能识别格式规整的东西，识别不了「G 校东门第三栋」。

第三，出站方向现在是裸的。入口干净 + 公开出口走人审，是我目前的答案，但它依赖入口真的干净。如果哪天加了新的数据入口忘了过脱敏，出口没有任何网。

第四，agent 主动开口要凭据的场景（比如逆向新站点时）还没有正规通道，目前靠人肉。我设想的做法是审批按钮加超时默认拒绝，凭据走环境变量注入、不进对话文本，但还没做。

## 我现在怎么过一遍隐私检查

1. 先看数据源：这条内容能不能定位学校、房间或个人？
2. 再看可见面：这个东西 agent 有没有必要看见？不必要就隔离，而不是看见了再删。
3. 然后看模型请求：必须发的部分，能不能换成假值？
4. 接着看展示对象：适合群聊、单聊，还是只适合本机？
5. 最后看组合信息：单独不敏感的几条，拼起来会不会暴露位置和作息？

以前我更容易只盯着「有没有明文手机号」。现在更担心的是「学校 + 宿舍 + 时间 + 日常行为」这种组合。生活隐私往往不是泄露一个字段，而是把一个人的轮廓慢慢拼出来。

这个月真正沉淀下来的，是两层筛子。第一层问「这道防线对应哪个真实威胁」，答不上来的拆掉，出口审计和网络审计就是这么没的。第二层问「能不能让它根本看不见」，能隔离的不脱敏，配置裁剪和文件快照就是这么来的。

该公开的是逆向过程、接口规律、代码结构和踩坑经验；该藏起来的是学校、房间、姓名、联系方式，以及那些拼起来就能描述你日常生活的细节。把方法留下，把生活轨迹删掉，比一句「已脱敏」难，也有用得多。
