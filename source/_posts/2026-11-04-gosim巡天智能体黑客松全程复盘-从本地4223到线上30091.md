# GOSIM 巡天智能体黑客松全程复盘：六天，从本地 4223 到线上 30091

## 比赛是什么

GOSIM "智能体巡天"（survey26）黑客松：你的智能体接管一台（模拟的）光谱巡天望远镜，在一整个观测季里自主决定每次曝光的指向、时长、观测程序和光纤分配。它看不到真实天气，只能靠每 15 分钟一条的简报猜；仪器会随机坏、指向会漂、地震会让数据作废；整季的墙钟预算只有 900 秒。

计分也很"天文台"：required 必观测目标漏一个罚 50，限时请求窗口内完成有加成，正确举报仪器故障 +100、误报 -150，剩下的大头是把科学产出（完成度 × 波段倍率 × 天气因子）最大化。比赛分两阶段：练习卡 A–D 上的榜单 purely cosmetic，**最终排名只看 4 张隐藏卡 E–H，每张跑 3 次取平均**——官方明说，"变化幅度和 A–D 差不多，请让智能体根据运行时收到的信息做决定，不要把策略写死"。

我们的智能体用 Rust 写在官方 rust-pro 基座上，六天里线上分数从 22444 爬到 30091，最终提交锁定 48c46ca4。这篇是全程复盘：哪些判断救了我们，哪些判断差点杀死我们。

## Day 0：情报先行，本地基线 4223 → 4846

比赛平台是个没有"文档页"的 SPA，但 SPA 意味着所有内容都在 JS chunk 里。把前端 bundle 拉下来，用正则从 minified 字符串里提取出完整规则和练习卡说明，配上讲座转写 PDF，整理成五份需求文档进了仓库。很多后来在代码里踩的坑，文档里其实都写了。

教训：**转写文本不可全信**——讲座转写里"9900 秒"实际是 900 秒，凡是关键数字和命令，一律以书面文档和代码交叉验证。

跑通官方示例后没有急着改代码，先做失分归因，发现三处白送的分：

1. 限时请求完成率 0%——代码里对 `observation_request` 消息类型零引用；
2. required 目标漏网 15 个（-750），且有个反直觉 bug：失败越多的目标被指数级降权（0.7^attempts），越失败越不再尝试；
3. 900 秒墙钟只用了 4%。

三处修复（请求感知调度、required 豁免失败阻尼 + 末夜保底、Hard mode `state_resync` 账本重建）合计 +623，本地四卡从均分 4223.3 到 4845.9。另有一个隐藏较深的 bug：地震公告会在整个恢复期每个 slot 重播，而故障检测的证据池要求"干净"样本——地震让所有样本永久不干净，故障证据冻结。把地震从公告集合剔除后，三张卡各 +100。

## Day 1：本地和云端是两个世界

把 agent 交到平台跑练习卡，第一课来了：**本地回归不通过不上线的纪律，对结构性改动要例外处理**。一个本地 -165 的改动（临界曝光策略）云端四卡全正 +850；一个本地 no-op 的改动（方向系数）云端 -502。本地卡和云端卡目标分布不同，观测序列一变，所有依赖序列模式的子系统都跟着重排。

这个现象的最灵敏探针是**故障举报链**。正式赛冲刺日我们连做 5 个序列改动，4 个死于同一症状：L3 卡的举报链断裂（rep 100 → 0）。机理是任何改变观测序列的"小改动"都会扰动故障证据的证据池模式，让原本能触发的举报差一口气。误报在免罚额度内成本为 0，漏报真实故障是 -100 加复利损失——**举报策略必须保持激进，而举报链是这个系统里最脆弱的组件**。

## LLM 建议轴：六连败，和"只记录不应用"

比赛要求智能体有 ≥2 个 LLM 驱动环节，于是我们把模型建议接进了调度。然后是连续六轮云端实验：

| 版本 | 云端均分 |
|---|---|
| 纯规则兜底（LLM 全灭） | **4444–4448** |
| MiniMax 原始建议 | 4235 |
| 温和折扣 + 时长收紧 | 3876 |
| 避让建议须实据 | 4158 |
| 时长裁剪 ±2% | 4138 |
| 时长建议钉死 1.0 | 3999 |

全部输给纯规则。逐晚日志给出了原因：模型会输出 `avoid=[八个方向全避]`（等于今晚别干活）、会给出 0.98/0.99/1.02 的逐晚时长抖动——**百分比级的时长扰动每晚都在掷骰子**，一批处在及格线边缘的 required 目标就这么擦线失败。即便方向正确的避让建议（公告确认的地形遮挡），应用后也会扰动序列、打乱举报时机。

最终方案：**建议全链路保留（调用、解析、实据校验、追踪、故障确认否决），但数值只记录不应用**——行为收敛回确定性规则，LLM 环节真实存在且可审计。后来在 v5 探针上复测，启用模型与否的净效应 ≈ 0。这条轴的结论很清晰：在这个确定性可判分的场景里，无约束的 LLM 建议是负期望；LLM 的输出永远要过一层确定性校验，怎么强调都不为过。

## 正式赛：换对探针，+3200

10/5 开赛当天我们踩了个决策陷阱：练习卡上请求加成判负（-239），我们就没带上它。直到线上榜跌到 #34 才反应过来——**docs 里明写隐藏卡与 A–D 同构，线上 A–D 才是 E–H 的同构 proxy，练习卡证据权重应该更低**。带加成的版本线上 A–D 一测 +892，其中 B 卡 required 漏网 22 → 0 是真实收益。

此后所有决策只认 A–D 实测。请求加成阶梯爬到饱和：

- 弱公式 22444 → ×2-6 23887 → ×3-8 24105 → ×4-10 **24332** → ×5-12 24316（首次衰退，停机）
- 请求余量 +0.25：+1288（机理是让"擦线档"请求真正过线）；+0.40 判负 -376——余量轴有峰
- required 余量 +0.25：+13，final 25633.81

同期待判负并永久封存的：每目标吞吐量修正 k_corr（本地四卡全涨、云端 C 卡塌 -1146——本地全绿 ≠ 云端安全，此课交了两轮学费）、部分加成救暗源 required（三次尝试全雪崩，锚点贪心框架内无解）、更深的锚点搜索（ANCHORS 6→12 线上 -3062：**算力不是瓶颈，贪心目标的结构性近视才是**——这个结论直接枪毙了我们的自研 Rust 移植）。

## 基座革命：官方 rust-pro，+4300

痛定复盘时发现了一个尴尬的事实：官方仓库 `examples/` 下一直躺着 python-pro 和 rust-pro 两个高级示例，而我们从 10/1 起步到 10/5 从未盘点过官方资料。自研 Rust 移植判负后，我们把基座换成了官方 rust-pro——它的增量排序 `gain = weight × (reach(T)×mult − best_so_far)` 天然解决覆盖率问题，本地四卡碾压我们移植的 python 版 +21.9%，线上直接从 25713 跳到 29945（**+4232，全程最大单笔收益**）。顺带修掉平台构建沙箱的两个坑：manifest 必须 `jsonl-v4`、`/usr/local/cargo` 只读需重定向 `CARGO_HOME`。

流程教训写进了开发文档：**每轮大改前核对官方资料**。我们赌了一个"官方只给了玩具基线"的假设，赌输了四天的移植工时（不过移植工作也没白费——它逼我们把协议和计分公式逐条吃透，后来排查基座差异全靠这层理解）。

## 旋钮时代：30091 与泛化联赛表

rust-pro 的调参全部走 `PRO_*` 环境变量、零源码改动——这也是防过拟合纪律的载体：任何阈值都不绑定卡片特征，光纤数、夜数、季节全部从 `initialize` 读。

- λ（稀疏度权重）0.6→0.45：本地 +632，唯一四卡全正；邻域 0.42/0.48 双侧判负，峰值真实
- POOL=900：意外 +548
- REFINE_ROUNDS=6：唯一兑现的搜索深度旋钮，线上 +31
- 邻域半径 2.1→3.0：密卡 C/D 兑现 +268
- 其余 14 档全部判负。旋钮改动的**本地→线上传导率约 10%**（本地 +838 只兑现 +88），一切以线上 A/B 为准

关键的平台性质：行为不变的卡分数逐分相同——线上 A/B 的分差都是真实效应，没有噪声借口可以躲。同时发现每轮线上评测自动附带 A1–D1（v5 风格卡），是 E–H 泛化的最佳探针。单卡噪声 ±1500，但**四卡均值噪声只有 ±43**——于是 final 决策改为 A1–D1 双跑均值联赛表，rr6 版本以 24843 夺冠（第二名 24562），10/6 锁定 48c46ca4。

## 情报解码与 intel 事故：E 自归一化盲区

v5 卡上有个漂亮的设计：51–90 个零分"请求"（RQ1xxx），`completion_reward=0`、`score_delta=0`——它们是**情报载体**。reason 字段是交接班日志，藏着凯撒密码（位移 = 当日日期）、摩斯码、唱名数字编码的真实站点信息：真实山脊线（公告把山建成 50° 平墙，实际西南 35°、南 43°）、停机维护窗口、对过期预报的纠偏。

我们做了 LLM 情报解码器：每晚后台收集新文本喂给模型，要求输出结构化 JSON（方向→真实山高、维护窗口 UTC），严格校验非法即回退规则值。本地经典卡逐分不变（无情报文本时零调用）。

然后是全程最大的事故。intel4 上线，Kimi 链路全通，结果 A1 **-36842**、B1 **-96020**。

事故链重建花了一夜：这台望远镜的故障检测全靠 E 值（质量/波段比值），而**波段基线会随坏数据自适应下滑**——仪器一坏，基线跟着沉，E 自归一化回 ~1.00，三条举报规则全盲。拖了 52 夜故障才被自然修好，required 大面积漏网。更扎心的是反推 rr6 的历史高分：它的故障恰好发生在健康基线建立之后，E 能掉下去才被看见——**纯属运气**。若 E–H 某张卡第一夜出故障，我们的 final 同样裸奔。

修复（commit c4e4e31）：scale 崩塌绝对触发器——连续观测小时 scale ≤0.12 钉地板且无全天天气公告 → 直接举报，绕过一切比值证据。阈值三档迭代 16h → 10h → 确认过一次故障后 5h。同卡序列说话：

| 版本 | A1 | B1 |
|---|---|---|
| intel4（无修复） | -36842 | -96020 |
| intel5（16h） | -6996 | -30013 |
| intel6（10h） | -2675 | — |
| intel7（10h/5h） | **-1128.84** | -14938.42 |

日志还揭示了这张卡的本质：故障每 2–4 天复发，一次触发 18 次——**这是探测速度的军备竞赛**，检测每慢一小时就多报废一小时曝光。

一个值得记录的方法论细节：A1 的 scenario 哈希与 rr6 完全相同，但每次运行气象和故障都是重采样的——**单轮 v5 分数不可比，只有分布可比**。这也意味着 intel7 与 intel8（仅模型等待超时 20s→6s 之差）在 A1/B1/C1 上分毫不差这件事，恰好证明低思考档位下模型行为近乎确定性。

## 截止之后：诚实的对照实验

10/8 截止，final 锁定 rr6，平台确认 locked。但故事还有下半场，而且是对"历史高分"最无情的一击：

换新模型服务后做同配置对照，**没有故障修复的 rr6** 在 A1–D1 上跑出 -36210 / -86239 / -46710 / -17936，而带修复的 rr6sfix 是 -1129 / -14938 / -6543 / 32805。两组都叠加了平台重试与模型停用，不能精确归因，但方向性结论成立：**rr6 在 v5 上的历史高分不能外推为泛化保证，scale 触发器是真实的保险**。

钱也烧完了——新模型账户余额 -0.48 元，线上日志一片 HTTP 402。于是最后一轮实验全部转为不花钱的本地合成验证：新增默认关闭的 `PRO_SCALE_INDEPENDENT`（绝对质量证据不依赖 E 是否形成、修复后清空、误报后需三小时恢复再武装），用固定七类场景（健康/首夜故障/晚发/复发/公告坏天气/未公告坏天气/地震）做开关对照，真值只交给 runner、agent 不读；参数不变做留出验证——首组三类故障 +10749/+1389/+11800，留出组 +56/+24/+2，四类对照逐分不变零误报。首组的大幅涨分**不能外推**，但"缺健康基线时更快修复严重故障"这个命题在两个独立场景组上都成立了。12 项 Rust 测试含 401/402/403 后停用模型调用的保护逻辑，全绿。

这个开关最终没能赶上参赛版本——证据到位时比赛已经锁定。它留在仓库里，默认关闭。

## 结局

最终提交：**rust-pro 基座 + λ0.45 + POOL900 + REFINE6 + 请求加成 ×4-10 + 双余量 0.25 + scale 故障触发器（intel7 系）中实测最强的 rr6 配置（48c46ca4）**。练习探针上 A–D 均分 ~30071（线上榜 #20 左右，#1 = 33530），A1–D1 泛化均值 24843。最终名次由隐藏卡 E–H 每卡 3 次评测取平均决定，以官方公布为准。

没能进前六。榜单头部的队伍在我们审计为"框架极限"的缺口上（裸科学分 ~1300/卡）找到了突破口，这是我们收敛太早、把"锚点贪心框架内无解"当成"无解"的代价。但六天里产出的方法论——探针选择决定决策质量、分布思维、确定性校验、防过拟合纪律——全部沉淀在 [gosim-survey26-agent](https://github.com/windy664/gosim-survey26-agent) 的 docs/ 里，下一次还会用。

## 反直觉教训清单

1. **本地全绿 ≠ 云端安全**。本地/云端分布不同，序列类改动的二阶效应本地根本不会发生。结构性改动必须云端 A/B，且只信与隐藏卡同构的卡种。
2. **最灵的探针往往是最脆的组件**。我们的故障举报链对一切序列扰动敏感——它既是最好的回归哨兵，也是最常被误伤的受害者。找到你系统里的"L3 举报链"，每轮改动先看它。
3. **确定性场景里，无约束的 LLM 建议是负期望**。六轮云端实验全输给纯规则；"只记录不应用"既保留了评奖要求的 LLM 环节，又保住了分数。
4. **自适应基线会吞掉它本该检测的异常**。E 值的波段基线随坏数据下滑、自归一化——用自适应统计量做异常检测时，必须配一条与基线无关的绝对证据通道。
5. **单轮分数不可比时只有分布可比**。同 scenario 哈希 ≠ 同实例；四卡均值把噪声从 ±1500 压到 ±43，用它做决策。
6. **排行榜会骗人，规则文档不会**。"练习卡判负"差点让我们丢掉 +892 的真实收益，因为忘了读"隐藏卡与 A–D 同构"那句话。
7. **每轮大改前盘点官方资料**。官方 examples 里躺着 +4300 分的基座，我们四天没看。
8. **过拟合纪律要落在机制上，不是口头上**。所有阈值走环境变量旋钮、设备参数从 initialize 读、合成验证配留出组、首组大涨不外推——这套约束在六天里至少拦下了三次我们想"就这一张卡调一下"的冲动。
