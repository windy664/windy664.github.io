# 一切透明的都在卡：我的 GNOME 卡顿批判书，以及我对 Omarchy 的期待

## 前言：一篇迟到的檄文

这个博客平时写的都是逆向、Agent、Minecraft 插件这类"正经"技术文。今天不写那些，今天我要写一篇檄文——被告是 GNOME，罪名是：在我这台配置完全够用的笔记本上，把桌面动画跑成了 PPT。

写这篇文章的直接导火索是今晚的一次普通操作：我按了一下 `Super` 键想切个工作区，然后眼睁睁看着四个窗口的缩略图以大约 24 帧、甚至更低的帧率，一卡一卡地飘进 Overview。与此同时，后台还跑着一个编译任务，CPU 占用还不到一半，内存剩 13GB——**硬件没有任何理由做不到 60 帧，但 GNOME 就是做不到。**

更讽刺的是，罪魁祸首不是什么复杂的科学计算，而是一个字：**透**。Dock 是透明的，Overview 是透明的，通知是透明的，应用文件夹是磨砂的，甚至我的终端、编辑器和笔记都被扩展蒙上了一层毛玻璃。这个桌面的美学信仰是"一切皆透明"，而这个信仰的代价由我的帧率来支付。

在开骂之前，先立此存照：

![案发现场全景：透明 Dock、顶栏音乐胶囊、毛玻璃扩展们，以及一块正在掉帧的 4K 面板](/posts/gnome-lag-omarchy/01-desktop.jpg)

## 被告档案：一台不该卡的机器

先看看被告席对面，也就是我这台"原告"的配置：

| 部件 | 规格 | 备注 |
|------|------|------|
| CPU | Intel i7-1185G7（4 核 8 线程，TigerLake） | 11 代酷睿，带 Iris Xe 核显 |
| 核显 | Iris Xe Graphics（96 EU） | GNOME 实际渲染主力 |
| 独显 | NVIDIA MX450（TU117，2GB） | 全天待机，基本不看戏（见后文） |
| 内存 | 32GB | 卡顿时常驻 17GB，余量充足 |
| 屏幕 | 4096 × 2304 面板（约 944 万像素），100Hz | GNOME 里实际跑 2560×1440 + 125% 缩放 |
| 系统 | Ubuntu 26.04 LTS，GNOME Shell 50.1 | 内核 7.0.0-38，Wayland 原生会话 |

请诸位品一品这张表：11 代 i7、32GB 内存、两块 GPU，2026 年，内核都迭代到 7.0 了。这套硬件跑个桌面环境，还要什么自行车？要求很低：**切工作区的时候，窗口别一抽一抽的。**

但 GNOME 表示：做不到。而且它做到了让"做不到"看起来理所当然。

## 罪状一：一切皆透明，一切透明都在卡

GNOME 及其扩展生态对"透明"的执念，已经到了宗教的程度。我把这台机器上正在生效的半透明效果一条条列出来，算是呈堂证供：

1. **顶栏的模糊，是我亲手关掉的**。我装过 `transparent-top-bar-tweaks`，也配过 Blur My Shell 的面板管线，如今 `dconf` 里躺着一行 `blur=false`——连顶栏要不要透明，都成了我需要定期查房的开销。
2. **Dock 是 80% 透明度的**。`dash-to-dock` 的 `background-opacity` 被我调到 0.8，看起来很美，代价是那一条 4096 像素宽的圆角长条，每一帧都在和壁纸做 alpha 混合。
3. **Overview 是透明的**。按下 `Super`，所有窗口缩略图、工作区条、搜索框，全员半透明。
4. **应用文件夹是磨砂的**。Blur My Shell 的 app folder 默认挂高斯模糊——这是 blur 家族里最贵的一档。
5. **我的编辑器、笔记和终端是毛玻璃的**。这是最离谱的一条，下一节单独审判。

有人可能要说：透明能费几个 GPU？那我们来算笔账。

这块屏幕是 4096 × 2304，约 **944 万像素**，是 1080p（约 207 万像素）的 **4.56 倍**。半透明不是"画一次就完"，它意味着每一帧都要把两层像素读出来、按 alpha 加权混合、再写回去；模糊更狠，还要做降采样、多轮卷积、升采样。这些操作全部吃显存带宽，而 Iris Xe 的带宽是和 32GB 内存共享 LPDDR4x——也就是说，GPU 模糊一帧窗口， CPU 的缓存也要跟着陪葬。

于是一个荒诞的场面出现了：我花大价钱买的 4K 屏，最后被用来放大"卡顿的细节"。在 1080p 时代勉强及格的模糊特效，乘以 4.56 之后，就是一帧 30ms 起步的渲染税。**GNOME 的美术同学在设计图前是艺术家，落在我的 Iris Xe 上是纵火犯。**

## 罪状二：我给编辑器、笔记和终端开了毛玻璃，这是我最忏悔的一件事

下面这段配置来自我机器上 Blur My Shell 的 live `dconf`，不是文学创作：

```ini
[applications]
blur=true
enable-all=false
opacity=214
unblur-when-fullscreen=true
dynamic-opacity=false
pipeline='pipeline_migrated_dynamic_blur'
whitelist=['md.Obsidian', 'dev.zed.Zed', 'org.gnome.Ptyxis']
```

翻译一下：**Obsidian、Zed、Ptyxis（GNOME 的终端）**，我日常盯得最久的三个窗口，全部加了毛玻璃，透明度压到 214/255。更早的时候，白名单里还关押过 `jetbrains-idea`、`code`、`jetbrains-pycharm`——后来在一轮"戒断手术"里才换成现在这三位。

当年是怎么想的？大概是深夜刷了某位 YouTube 博主的 rice 视频：毛玻璃的编辑器，透出背后的雪山壁纸，"啊，这就是 Linux 桌面的浪漫"。我冲动了。我居然觉得一个每秒钟要重排几万行文字、渲染语法高亮和诊断波浪线的编辑器，还应该**额外**负责展示它身后的壁纸。

结果就是：长文档一滚动，毛玻璃后面那层糊掉的像素就跟着一抖一抖，仿佛整个编辑器坐在一辆减震器坏了的车里。后来我学乖了：关掉"默认全部启用"、开了"全屏时取消模糊"、只留白名单——**看看这套配置，哪里是美化，分明是一个卡顿受害者的投降书。**

![忏悔证据：Blur My Shell 白名单里关着 Obsidian、Zed 和 Ptyxis](/posts/gnome-lag-omarchy/02-blur-whitelist.jpg)

## 罪状三：卡顿的日常，五幕循环惨剧

如果不罗列几个日常场景，批判就不够具体。以下场面每天循环播放：

- **按 `Super` 打开 Overview**：窗口缩略图集体飘入，飘入过程一顿一顿，像信号不好的视频通话。搜索框已经能打字了，动画还在播上一秒的残影。
- **切换工作区**：整个桌面横向滑动的动画掉帧，窗口边缘出现"数字化"的拖影。四个工作区来回切一圈，感觉像在翻一本受潮的杂志。
- **拖动窗口**：IDEA 这类重型窗口一拖，身后跟着断断续续的残影，鼠标指针和窗口内容偶尔脱钩半厘米。
- **通知弹窗**：右上角一条透明通知滑入的瞬间，正在播放的视频必然丢一帧。通知越美，视频越卡。
- **打开 Dash 里的应用**：图标缩放动画进行到一半，应用窗口已经开始渲染了，两者在空中尴尬地交汇。

每一项单拿出来都不致命，加在一起就是一句话：**这个桌面让我在 2026 年提前体验了 24 帧的怀旧美学。**

![卡顿现场：按下 Super 之后的 Overview，全员半透明阵容](/posts/gnome-lag-omarchy/03-overview.jpg)

## 罪状四：独显在看戏，核显在加班

这台机器里有一块 NVIDIA MX450。它平时的工作状态是这样的：

| Fan  Temp   Perf                        | Pwr:Usage/Cap          | Memory-Usage         |

|   0  NVIDIA GeForce MX450          Off  | 00000000:01:00.0  Off  |                  N/A |

**0% 利用率，3MiB 显存。** 全进程列表里唯一的客户是 `gnome-shell`，占用 1MiB——这块显卡全天的工作，就是替合成器保管 1MiB 显存，顺便把自己烘到 59 度。驱动还给它标了 `5001W` 的功率墙，算是 nvidia-smi 每天准时上演的一次浪漫主义文学创作。

我理解混合显卡的电源管理逻辑：核显续航好，独显按需唤醒。可是 GNOME 从未给过我一个体面的"渲染后端"选项——没有"用独显合成桌面"的开关，没有"动画降级"的档位，连个官方的"性能模式"都没有。MX450 就这么躺在 PCI 总线上，看着 Iris Xe 在 4K 毛玻璃下气喘吁吁，自己吹着 0 转的风扇。

一块花了真金白银买来的显卡，在 Linux 桌面上的全部存在感，是让设备管理器里多一行字。这不是 MX450 的失职，这是桌面环境调度哲学的失职。

## 罪状五：我买了一块 4K 屏，却被迫用"2K + 渲染税"过日子

先看一张被告席证物——这是我"设置 → 显示器"页面的真实截图：分辨率写着 **2560 × 1440**，缩放 **125%**，刷新率 **100Hz**，"旧版应用内缩放"（`xwayland-native-scaling`）开着。

![被告席证物：4K 面板，跑着 2560×1440 + 125% 的缩放套餐](/posts/gnome-lag-omarchy/05-display.jpg)

但 `xrandr` 不会说谎：

```text
4096x2304     99.97*
```

当前渲染缓冲区**仍然是 4096 × 2304**。也就是说，GNOME 的这套"分辨率 + 缩放"套餐实际是：mutter 按 944 万像素渲染完整画面，缩到 2560×1440 模拟一块"2K 屏"，再在逻辑桌面上套 125% 的 UI 缩放（有效逻辑分辨率约 2048 × 1152）。**翻译成人话：我花 4K 屏的钱，看 2K 的桌面，交的却是全额 4K 渲染税。** 每一层透明、每一次模糊，都发生在 4096 × 2304 的缓冲区里。

顺带一提，这块面板本来能跑 100Hz。100Hz！如今我实际获得的丝滑度，大约是 30fps 的幻灯片在模拟。还有一块缩放的历史伤疤：`monitors.xml` 里至今留着一份 1.333 倍分数缩放的旧档——每次换缩放档位，所有窗口都要集体重排一次。这很 GNOME。

至于应用层：Zed 是 Wayland 原生的，在这一切之下还能维持体面；而 JetBrains 全家桶这类 XWayland 时代的"渲染大户"，`xwayland-native-scaling` 救了清晰度，救不了帧率。终端里的 `htop` 不会说谎：切一次工作区，`gnome-shell` 的 CPU 占用就窜上一个明显的高峰，而屏幕上的动画依然在掉帧。**渲染管线已经饱和到"多开一个模糊就掉帧"的程度，GNOME 却假装一切安好。**

## 我的自救史：从用户到民间补丁匠

骂完了被告，轮到我这个原告自首：这些年我为了治卡顿干过的事，说出来一半会让人以为我是 GNOME 的维护者。我的家目录里躺着一个 `ubuntu-optimization-backups/` 目录，里面是历次"手术"的备份与病历：

```text
ubuntu-optimization-backups/
├── 20261013-220727/
├── apt-refresh-fixed.log
├── blur-apps-only-20261013-230143   # 那次我下决心把毛玻璃限制在白名单里
├── gpu-20261013-221111              # 折腾混合显卡调度的痕迹
├── gnome-fix/
│   ├── gnome-shell_50.1-0ubuntu1.3_amd64.deb   # 下载官方 deb 对照源码
│   ├── original-syncStacking.js                # 我改掉的那份原始文件
│   └── rollback.sh                             # 手滑时的后悔药
├── gnome-workspace-commits.json     # 追踪上游 workspace 动画修复的记录
├── input-method-20261014-103816
├── solar-appearance
└── topbar-20261013-224842           # 透明顶栏的调参现场
```

没错，我干过这些事：

1. **调参党阶段**：`vm.swappiness` 压到 10，关掉各种后台服务，换壁纸解码更快的图源。有用，但没用——该卡的动画一帧没少。
2. **裁缝阶段**：把 Blur My Shell 从"全局模糊"改成"仅白名单应用"，`sigma` 从 30 降到 0，透明度一点点往上加，一帧一帧地试。这段经历让我精通了"如何在 4K 下用肉眼测帧率"。
3. **魔改源码阶段**：工作区切换行为不对劲，我直接把 `gnome-shell` 的 JS 源码翻出来对照，本地打了补丁，还顺手写了个私有扩展 `workspace-stacking-fix@local.windy` 挂在扩展列表里。备份、回滚脚本一应俱全。
4. **追上游阶段**：维护着一份 `gnome-workspace-commits.json`，盯着 GNOME 上游关于 workspace 动画的修复提交，等它们进 Ubuntu 的仓库。

一个桌面环境的最终用户，最后练出了"下载发行版 deb 对照源码、本地改 JS、写私有扩展、追上游 MR"的全套技能——**这究竟是用户的荣耀，还是桌面环境的耻辱？**

## 批判的升华：问题不在毛玻璃，在于没有退路

写到这里，必须公道地说一句：毛玻璃本身不是罪。模糊、透明、动画，作为审美选择无可指摘，Windows 11 和 macOS 也都是这个路线，人家跑得也不差。

GNOME 真正的问题在于三点：

**第一，性能与效果的取舍权从来不在用户手里。** GNOME 没有一个"性能模式"，没有"渲染质量"分级，甚至没有一个官方的"全部关掉透明"的总闸。`enable-animations` 倒是有，可关掉动画的 GNOME 就像关掉灯的舞台——美术集体下班，只剩功能骨干在裸奔。一个成熟的产品应该给低配机器一条体面的退路，而不是让用户在"卡顿的浪漫"和"裸奔的朴素"之间二选一。

**第二，"默认体验"只为参考配置服务。** GNOME 团队的测试机大概不是 4K + 分数缩放 + Iris Xe 的组合。默认值在参考机上丝般顺滑，落到我的机器上就是 24 帧幻灯片。社区里问这类问题，标准答案永远是三件套："换固态吧""内存加了吗""你这 CPU 不行"——我 32GB 内存加 i7，还要怎样？**没人愿意承认：是特效的默认值背刺了非参考配置。**

**第三，修起来没有尽头的"私有复杂度"。** 我一个写 Rust 和 Java 的，为了桌面顺滑，被迫去读 `gnome-shell` 的 JS、追上游的 MR、写 GJS 扩展。这套系统的复杂度深不见底，而它对外的承诺却是"简单，不做配置"。**不做配置的意思是：要么接受默认，要么自己变成开发者。没有中间态。**

以上三条，就是我写下这篇批判书的全部理由。

## 曙光：Omarchy，我的新期待

骂也骂完了，总要给生活一点盼头。盼头就是标题里的另一位主角：**Omarchy**。

关注它的朋友都知道，这是 DHH（Ruby on Rails 之父，那个永远在"重写一切"的男人）主导的 Arch + Hyprland 发行版，口号是"opinionated"——和你意见一致时是"有主见"，不一致时是"独断专行"。昨晚我已经忍不住动手了：下载 Omarchy 4.0.6 的 ISO，写无人值守脚本，用 QEMU/KVM + cloud-init 把它装进虚拟机，如今这台 VM 已经在 libvirt 里安家、无头常驻。安装日志的最后一行看起来非常治愈：

```text
[  OK  ] Reached target Network.
[  OK  ] Started OpenSSH Daemon.
Omarchy 7.2.8-9-omarchy (ttyS0)

omarchy-vm login:
```

一次通过。Arch 系的安装体验被 Omarchy 做成了"回答五个问题，还你一个成品桌面"，这本身就是对传统 Linux 发行版的一种嘲讽。（VM 桌面截图暂缺：这台 VM 的 SPICE 是 `listen type='none'` 的无头配置，宿主机截不到它的脸，哪天 virt-viewer 连上了再补一张。）

为什么我对它有期待？因为 4.0 "Quattro" 的更新清单几乎条条打在 GNOME 的痛点上：

- **整个桌面壳统一成了一个 Quickshell 进程。** 状态栏、启动器、通知、OSD、锁屏、polkit 弹窗，全在同一个进程里，插件化、IPC 可编程。对比 GNOME 那个"Shell + 一堆扩展进程 + 各自的 JS 沙箱"，这是架构层面的降维。
- **官方原话：事件驱动取代轮询，"an idle desktop stops burning CPU"。** 待机时不再空转烧 CPU——这句话对 GNOME 用户来说简直是科幻小说。
- **Hyprland 的配置换成了 Lua。** 绑定、监视器、开关都是可读可改的 `o.bind("SUPER + SHIFT + W", ...)`。也就是说，未来我调桌面，读的是 Lua 脚本，而不是去猜某个 GSettings 键值藏在哪棵 schema 树下。
- **效果全是 opt-in，全有一键总闸。** 想要毛玻璃可以自己开，想要透明双击状态栏就切换，不想要就关——**取舍权终于回到了用户手里**，这正是我批判 GNOME 的第一宗罪的反面。
- **swap 用 zram 调优、主题 24 色自动生成 btop/nvim/VS Code 配色、安装快到一分钟以内。** 细节处处透着"这台机器是我的，不是发行版的"。

当然，我也不是无脑吹，隐忧同样列在案：

1. **Arch 滚动更新的信仰之跃**。半路 `pacman -Syu` 挂了的传说听了十年，好在 Omarchy 更新走 Snapper 快照，出事能回滚——先在虚拟机里替大家踩雷。
2. **MX450 是张老卡**。Omarchy 对 NVIDIA 的检测已经很聪明（按设备 ID 分类，不再误唤醒休眠的 GPU），但 PRIME offload 的应用级调度还是得自己操心。
3. **HiDPI 要自己动手**。4K + 分数缩放这种组合，在 Hyprland 里就是 `monitor = eDP-1, 4096x2304@100, 0x0, 1.25` 一行配置——好在这是"自己写一行就解决"，而不是"无处可写"。

计划是这样的：虚拟机里先跑满一个月，把日常工具链（终端、IDE、微信、浏览器、Ru41 的运维面板）全部迁过去试水。如果帧率真的如传闻中那样"动画如丝、待机零烧"，就找个周末给这块 4K 屏一个重新做人的机会。

## 结语

最后总结一下这篇批判书的中心思想：

> **GNOME 给了我一切，唯独没给我帧率。它把"美"做成了默认值，把"快"做成了选修课，把"改"做成了炼狱难度。**

而我对 Omarchy 的期待，说白了只有一句话：**我不要更华丽的桌面，我要的是一个"一切皆可关"的桌面。** 透明想开就开、想关就关，动画要丝滑就丝滑、要省电就省电，配置读得懂、改得动、回得了头。

如果 Omarchy 4 在这块 4096×2304 的屏幕上，能把工作区切换跑满 60 帧，那么这篇批判书就当是写给 GNOME 的分手信；如果它也卡——那我大概会写一篇更长的批判书，并郑重考虑改行写渲染引擎。

（至于虚拟机里的 Hyprland 动画到底能不能满帧——等我跑满这一个月，下回分解。）

*——写于又一次等待 Overview 动画播完的深夜*
