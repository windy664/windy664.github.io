# 一切透明的都在卡：我的 GNOME 卡顿批判书，以及我对 Omarchy 的期待

## 事情的起因

被告是 GNOME，罪名是在一台配置完全够用的笔记本上，用半透明效果把桌面动画拖成了 PPT。

导火索是今晚一次很普通的操作。我按了一下 `Super` 键想切工作区，然后眼睁睁看着四个窗口的缩略图以 24 帧上下的帧率、一卡一卡地飘进 Overview。当时后台跑着一个编译任务，CPU 占用不到一半，内存还剩 13GB。硬件没有任何理由做不到 60 帧，但 GNOME 就是做不到。

更讽刺的是，拖后腿的不是什么复杂的科学计算，而是一个字：透。Dock 是透明的，Overview 是透明的，通知是透明的，应用文件夹是磨砂的，连我的终端、编辑器和笔记都被扩展蒙了一层毛玻璃。这个桌面的美学信仰是"一切皆透明"，代价由我的帧率来支付。

开骂之前，先放一张案发现场：

![案发现场全景：透明 Dock、顶栏音乐胶囊、毛玻璃扩展们，以及一块正在掉帧的 4K 面板](/posts/gnome-lag-omarchy/01-desktop.jpg)

## 机器本身不该卡

先看配置：

| 部件 | 规格 | 备注 |
|------|------|------|
| CPU | Intel i7-1185G7（4 核 8 线程，TigerLake） | 11 代酷睿，带 Iris Xe 核显 |
| 核显 | Iris Xe Graphics（96 EU） | GNOME 实际渲染主力 |
| 独显 | NVIDIA MX450（TU117，2GB） | 全天待机，基本不看戏（见后文） |
| 内存 | 32GB | 卡顿时常驻 17GB，余量充足 |
| 屏幕 | 4096 × 2304 面板（约 944 万像素），100Hz | GNOME 里实际跑 2560×1440 + 125% 缩放 |
| 系统 | Ubuntu 26.04 LTS，GNOME Shell 50.1 | 内核 7.0.0-38，Wayland 原生会话 |

11 代 i7、32GB 内存、两块 GPU，2026 年，内核都迭代到 7.0 了。我对它的要求低到不能再低：切工作区的时候，窗口别一抽一抽的。GNOME 给的答复是做不到，还把"做不到"做得理所当然。

## 透明的代价

GNOME 和它的扩展生态对透明的执念，我把自己机器上正在生效的半透明效果一条条列出来：

1. 顶栏的模糊，是我亲手关掉的。装过 `transparent-top-bar-tweaks`，也配过 Blur My Shell 的面板管线，如今 `dconf` 里躺着一行 `blur=false`——连顶栏要不要透明，都成了需要定期查房的开销。
2. Dock 是 80% 透明度的。`dash-to-dock` 的 `background-opacity` 调到 0.8，看着确实好看，代价是那条 4096 像素宽的圆角长条，每一帧都在和壁纸做 alpha 混合。
3. Overview 是透明的。按下 `Super`，所有窗口缩略图、工作区条、搜索框，全员半透明。
4. 应用文件夹是磨砂的。Blur My Shell 的 app folder 默认挂高斯模糊，这是 blur 家族里最贵的一档。
5. 我的编辑器、笔记和终端是毛玻璃的。这条最离谱，下一节单独说。

有人可能觉得透明能费几个 GPU，这笔账可以算一算。

屏幕是 4096 × 2304，约 944 万像素，是 1080p（约 207 万像素）的 4.56 倍。半透明不是画一次就完，它意味着每一帧都要把两层像素读出来、按 alpha 加权混合、再写回去；模糊更贵，还要做降采样、多轮卷积、升采样。这些操作全吃显存带宽，而 Iris Xe 的带宽是和 32GB 内存共享 LPDDR4x——GPU 模糊一帧窗口，CPU 的缓存跟着陪葬。

于是荒诞的地方来了：花大价钱买的 4K 屏，最后被用来放大"卡顿的细节"。1080p 时代勉强及格的模糊特效，乘以 4.56 之后，一帧 30ms 起步，这就是我说的渲染税。

## 毛玻璃是我自己开的

下面这段配置来自我机器上 Blur My Shell 的 live `dconf`，不是文学创作：

```ini
[applications]
blur=true
enable-all=false
opacity=214
unblur-when-fullscreen=true
dynamic-opacity=false
pipeline='pipeline_migrated_dynamic_blur'
whitelist=['md.Obsidian', 'dev.zed.Zed', 'org.gnome.Ptyxis']
```

翻译一下：Obsidian、Zed、Ptyxis（GNOME 的终端），我日常盯得最久的三个窗口，全部加了毛玻璃，透明度压到 214/255。更早的时候，白名单里还关押过 `jetbrains-idea`、`code`、`jetbrains-pycharm`，一轮"戒断手术"之后才换成现在这三位。

当年怎么想的？大概是深夜刷了某个 YouTube 博主的 rice 视频：毛玻璃的编辑器，透出背后的雪山壁纸。我冲动了。一个每秒钟要重排几万行文字、渲染语法高亮和诊断波浪线的编辑器，居然还被我安排了一份额外工作：展示它身后的壁纸。

结果就是长文档一滚动，毛玻璃后面那层糊掉的像素跟着一抖一抖，整个编辑器像坐在一辆减震器坏了的车里。后来我学乖了：关掉"默认全部启用"、开了"全屏时取消模糊"、只留白名单。回头看这套配置，哪里是美化，分明是一个卡顿受害者的投降书。

![忏悔证据：Blur My Shell 白名单里关着 Obsidian、Zed 和 Ptyxis](/posts/gnome-lag-omarchy/02-blur-whitelist.jpg)

## 卡顿的日常

以下场面每天循环播放：

- 按 `Super` 打开 Overview：窗口缩略图集体飘入，飘入过程一顿一顿，像信号不好的视频通话。搜索框已经能打字了，动画还在播上一秒的残影。
- 切换工作区：整个桌面横向滑动的动画掉帧，窗口边缘出现"数字化"的拖影。四个工作区来回切一圈，感觉像在翻一本受潮的杂志。
- 拖动窗口：IDEA 这类重型窗口一拖，身后跟着断断续续的残影，鼠标指针和窗口内容偶尔脱钩半厘米。
- 通知弹窗：右上角一条透明通知滑入的瞬间，正在播放的视频必然丢一帧。通知越美，视频越卡。
- 打开 Dash 里的应用：图标缩放动画进行到一半，应用窗口已经开始渲染了，两者在空中尴尬地交汇。

单看每一项都不致命，加在一起，就是这个桌面让我在 2026 年提前过上了 24 帧的怀旧生活。

![卡顿现场：按下 Super 之后的 Overview，全员半透明阵容](/posts/gnome-lag-omarchy/03-overview.jpg)

0% 利用率，3MiB 显存，进程列表里唯一的客户是 gnome-shell，占 1MiB。这块显卡全天的工作，就是替合成器保管 1MiB 显存，顺便把自己烘到 59 度。驱动还给它标了 5001W 的功率墙，算是 nvidia-smi 每天准时上演的行为艺术。

我理解混合显卡的电源管理逻辑：核显续航好，独显按需唤醒。可 GNOME 从未给过一个体面的"渲染后端"选项——没有"用独显合成桌面"的开关，没有"动画降级"的档位，连个官方的性能模式都没有。MX450 就这么躺在 PCI 总线上，看着 Iris Xe 在 4K 毛玻璃下气喘吁吁，自己吹着 0 转的风扇。

## 4K 屏跑着 2K 桌面

先放一张"设置 → 显示器"页面的截图：分辨率写着 2560 × 1440，缩放 125%，刷新率 100Hz，"旧版应用内缩放"（`xwayland-native-scaling`）开着。

![被告席证物：4K 面板，跑着 2560×1440 + 125% 的缩放套餐](/posts/gnome-lag-omarchy/05-display.jpg)

但 `xrandr` 不会说谎：

```text
4096x2304     99.97*
```

当前渲染缓冲区仍然是 4096 × 2304。也就是说，GNOME 这套"分辨率 + 缩放"套餐的实际工作方式是：mutter 按 944 万像素渲染完整画面，缩到 2560×1440 模拟一块 2K 屏，再在逻辑桌面上套 125% 的 UI 缩放（有效逻辑分辨率约 2048 × 1152）。我花 4K 屏的钱，看 2K 的桌面，交的是全额 4K 渲染税。每一层透明、每一次模糊，都发生在 4096 × 2304 的缓冲区里。

顺带一提，这块面板本来能跑 100Hz，如今我实际拿到的丝滑度，大约是 30fps 的幻灯片。缩放这块还有个历史伤疤：`monitors.xml` 里至今留着一份 1.333 倍分数缩放的旧档，每次换缩放档位，所有窗口都要集体重排一次。

应用层这边，Zed 是 Wayland 原生的，在这一切之下还能维持体面；JetBrains 全家桶这类 XWayland 渲染大户，`xwayland-native-scaling` 救了清晰度，救不了帧率。终端里的 `htop` 不会说谎：切一次工作区，`gnome-shell` 的 CPU 占用就窜上一个明显的高峰，而屏幕上的动画依然在掉帧。渲染管线已经饱和到多开一个模糊就掉帧的程度，GNOME 假装一切安好。

## 自救史

骂完了轮到自首：这些年为了治卡顿干过的事，说出来一半会让人以为我是 GNOME 的维护者。家目录里躺着一个 `ubuntu-optimization-backups/` 目录，里面是历次手术的备份与病历：

```text
ubuntu-optimization-backups/
├── 20261013-220727/
├── apt-refresh-fixed.log
├── blur-apps-only-20261013-230143   # 那次我下决心把毛玻璃限制在白名单里
├── gpu-20261013-221111              # 折腾混合显卡调度的痕迹
├── gnome-fix/
│   ├── gnome-shell_50.1-0ubuntu1.3_amd64.deb   # 下载官方 deb 对照源码
│   ├── original-syncStacking.js                # 我改掉的那份原始文件
│   └── rollback.sh                             # 手滑时的后悔药
├── gnome-workspace-commits.json     # 追踪上游 workspace 动画修复的记录
├── input-method-20261014-103816
├── solar-appearance
└── topbar-20261013-224842           # 透明顶栏的调参现场
```

具体干过的事：

1. 压 `vm.swappiness` 到 10，关掉各种后台服务，换壁纸解码更快的图源。有用，但没用——该卡的动画一帧没少。
2. 把 Blur My Shell 从"全局模糊"改成"仅白名单应用"，`sigma` 从 30 降到 0，透明度一点点往上加，一帧一帧地试。这段经历让我精通了在 4K 下用肉眼测帧率。
3. 工作区切换行为不对劲，直接把 `gnome-shell` 的 JS 源码翻出来对照，本地打了补丁，还写了个私有扩展 `workspace-stacking-fix@local.windy` 挂在扩展列表里，备份、回滚脚本一应俱全。
4. 维护着一份 `gnome-workspace-commits.json`，盯着 GNOME 上游关于 workspace 动画的修复提交，等它们进 Ubuntu 的仓库。

一个写 Rust 和 Java 的最终用户，为了桌面顺滑，练出了下载发行版 deb 对照源码、本地改 JS、写 GJS 扩展、追上游 MR 的全套技能。

## 问题出在没有退路

公道话要说在前面：模糊、透明、动画，作为审美选择无可指摘，Windows 11 和 macOS 也都是这个路线，人家跑得也不差。

GNOME 的第一个问题，是性能与效果的取舍权从来不在用户手里。没有一个"性能模式"，没有"渲染质量"分级，甚至没有一个官方的"全部关掉透明"的总闸。`enable-animations` 倒是有，可关掉动画的 GNOME 就像关掉灯的舞台。一个成熟的产品应该给低配机器一条体面的退路，而不是让用户在"卡顿的浪漫"和"裸奔的朴素"之间二选一。

第二个问题，是"默认体验"只为参考配置服务。GNOME 团队的测试机大概不是 4K + 分数缩放 + Iris Xe 的组合，默认值在参考机上丝般顺滑，落到我的机器上就是 24 帧幻灯片。社区里问这类问题，标准答案永远是三件套："换固态吧""内存加了吗""你这 CPU 不行"——我 32GB 内存加 i7，还要怎样？没人愿意承认是特效的默认值背刺了非参考配置。

第三个问题，是这套系统的私有复杂度修起来没有尽头。不做配置的意思是：要么接受默认，要么自己变成开发者，没有中间态。我一个写 Rust 和 Java 的，被迫去读 gnome-shell 的 JS、追上游的 MR、写 GJS 扩展，就是上一节那套技能树的由来。

## 然后是 Omarchy

骂也骂完了，总得给生活一点盼头。盼头就是标题里的另一位主角：Omarchy，DHH（Ruby on Rails 之父）主导的 Arch + Hyprland 发行版，口号是 "opinionated"——和你意见一致时叫有主见，不一致时叫独断专行。

昨晚我已经忍不住动手了：下载 Omarchy 4.0.6 的 ISO，写无人值守脚本，用 QEMU/KVM + cloud-init 把它装进虚拟机，如今这台 VM 已经在 libvirt 里安家、无头常驻。安装日志的最后一行：

```text
[  OK  ] Reached target Network.
[  OK  ] Started OpenSSH Daemon.
Omarchy 7.2.8-9-omarchy (ttyS0)

omarchy-vm login:
```

一次通过。Arch 系的安装体验被 Omarchy 做成了"回答五个问题，还你一个成品桌面"。（VM 桌面截图暂缺：这台 VM 的 SPICE 是 `listen type='none'` 的无头配置，宿主机截不到它的脸，哪天 virt-viewer 连上了再补一张。）

4.0 "Quattro" 的更新清单，几乎条条打在 GNOME 的痛点上：

- 整个桌面壳统一成了一个 Quickshell 进程，状态栏、启动器、通知、OSD、锁屏、polkit 弹窗全在同一个进程里，插件化、IPC 可编程。对比 GNOME 那个"Shell + 一堆扩展进程 + 各自的 JS 沙箱"，这是架构层面的差距。
- 官方原话：事件驱动取代轮询，"an idle desktop stops burning CPU"。待机时不再空转烧 CPU，这句话对 GNOME 用户来说是科幻小说。
- Hyprland 的配置换成了 Lua，绑定、监视器、开关都是可读可改的 `o.bind("SUPER + SHIFT + W", ...)`。以后调桌面，读的是 Lua 脚本，而不是去猜某个 GSettings 键值藏在哪棵 schema 树下。
- 效果全是 opt-in，全有一键总闸。想要毛玻璃自己开，想要透明双击状态栏就切换，不想要就关——取舍权回到了用户手里。
- swap 用 zram 调优、主题 24 色自动生成 btop/nvim/VS Code 配色、安装快到一分钟以内，细节处处透着"这台机器是我的，不是发行版的"。

当然也不是无脑吹，隐忧列三条：

1. Arch 滚动更新的信仰之跃。半路 `pacman -Syu` 挂了的传说听了十年，好在 Omarchy 更新走 Snapper 快照，出事能回滚——先在虚拟机里替大家踩雷。
2. MX450 是张老卡。Omarchy 对 NVIDIA 的检测已经很聪明（按设备 ID 分类，不再误唤醒休眠的 GPU），但 PRIME offload 的应用级调度还是得自己操心。
3. HiDPI 要自己动手。4K + 分数缩放这种组合，在 Hyprland 里就是 `monitor = eDP-1, 4096x2304@100, 0x0, 1.25` 一行配置，好在这是"自己写一行就解决"，而不是"无处可写"。

计划是这样的：虚拟机里先跑满一个月，把日常工具链（终端、IDE、微信、浏览器、Ru41 的运维面板）全部迁过去试水。如果帧率真的如传闻中那样"动画如丝、待机零烧"，就找个周末给这块 4K 屏一个重新做人的机会。

## 最后

GNOME 给了我一切，唯独没给我帧率。我对 Omarchy 的期待也只有一句：我要的是一个"一切皆可关"的桌面——透明想开就开、想关就关，动画要丝滑就丝滑、要省电就省电，配置读得懂、改得动、回得了头。

如果 Omarchy 4 在这块 4096×2304 的屏幕上，能把工作区切换跑满 60 帧，这篇批判书就当是写给 GNOME 的分手信；如果它也卡，那我大概会写一篇更长的，并郑重考虑改行写渲染引擎。

（至于虚拟机里的 Hyprland 动画到底能不能满帧——等我跑满这一个月，下回分解。）
